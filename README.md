# LULZFORUM

**Чёрно-белый bitmap форум-мессенджер.** Лента рекомендаций, чаты и группы, теги, друзья,
личное хранилище файлов и музыка со всего интернета — в одном 1-битном интерфейсе.
Работает как статический сайт на **GitHub Pages**, данные и авторизация — **Supabase**.

## Что внутри

| Раздел | Возможности |
| --- | --- |
| **Лента** | Рекомендации (свежесть + лайки + ваши теги + друзья), режимы «Свежее / Подписки / Топ», закреплённые посты, «показать ещё», блок «может зайти» |
| **Посты** | Текст с `#тегами` и `@упоминаниями`, картинки (сжатие в браузере), прикреплённый трек, лайки, закладки, комментарии, копирование ссылки, удаление своих постов |
| **Чаты** | Личные диалоги и группы, вложения (фото/файлы), отметки о прочтении, счётчики непрочитанного, realtime-подписка, разделители дат |
| **Сообщества** | Группы с текстовыми каналами и голосовыми комнатами, вступление/выход, владелец, удаление каналов, список участников, создание своих каналов |
| **Музыка** | Поиск по открытым каталогам **Audius**, **iTunes**, **Openverse**, **Zaycev.net**, вставка ссылок **SoundCloud**, **Яндекс Музыки**, **Zaycev.net**, **YouTube**, **Bandcamp**, прямых mp3; «Моя музыка», лайки, плейлисты, полноценный плеер (очередь, shuffle, repeat, громкость, Media Session) |
| **Хранилище** | Приватные файлы, drag & drop, превью (изображения, аудио, видео), фильтры по типу, поиск, сетка/список, скачивание, подписанные ссылки, индикатор квоты |
| **Друзья** | Заявки в обе стороны, принятие/отклонение, отмена, список друзей, «написать в один клик», поиск людей |
| **Теги** | Тег из текста поста, архив тега, связанные теги, тренды, единый поиск |
| **Профиль** | Имя, ник, аватар (загрузка или пиксель-идентикон), био, ссылки, статистика, вкладки «Посты / Музыка / О себе» |
| **Уведомления** | Лайки, комментарии, заявки, сообщения, треки; «прочитать всё» |
| **Настройки** | Профиль, **переключатель темы (белое на чёрном ↔ чёрное на белом)**, режим доступа к Zaycev, уменьшение анимации, статистика данных, экспорт JSON, сброс демо-данных, горячие клавиши |
| **UX** | Горячие клавиши, PWA-манифест, адаптив до мобильных, скелетон загрузки, тосты, диалоги, лайтбокс, пиксельные иконки и идентиконы |

Всё оформление — **1-битное**: только `#000` и `#fff`, жёсткие тени, дизеринг-текстуры,
шрифты `Handjet` (дисплейный) и `JetBrains Mono` (текст). Никаких скруглений и градиентов.

**Две темы — и только две.** «Чёрное на белом» (по умолчанию) и «белое на чёрном»: это одна и та же
пиксельная геометрия с инвертированными ролями цвета. Переключатель — в шапке (квадрат из двух ячеек)
и в настройках. Выбор хранится в `localStorage['lulzforum:theme']` и применяется до первой отрисовки,
поэтому вспышки белого экрана нет. Авто-режима и третьей темы не предусмотрено — так и задумано.

### Сообщества и голосовые каналы

У сообщества есть владелец, участники и каналы двух видов:

* **текстовый** — тот же чат, что и в личных сообщениях (таблица `chats`, `kind = 'channel'`);
* **голосовой** — комната, звук в которой идёт напрямую между участниками по **WebRTC** (mesh),
  а сигналинг — через Supabase Realtime (`broadcast`), потому что у статического сайта нет сервера.

Микрофон включается только по кнопке «Подключиться», есть индикатор уровня, заглушение и выход.
Без Supabase голосовой канал работает в локальном режиме (микрофон и монитор уровня) и честно
об этом пишет. Для голоса между людьми нужны `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` и HTTPS —
STUN-серверы Google/Twilio используются только для установления соединения, звук никуда не пишется.

## Быстрый старт

```bash
npm install
npm run dev        # http://localhost:5173
```

Без переменных окружения приложение работает в **демо-режиме**:

* данные (посты, чаты, файлы, музыка) хранятся в **IndexedDB** браузера;
* кнопка «Войти в демо-аккаунт» открывает заранее наполненный профиль `@demo`;
* можно зарегистрировать свой локальный аккаунт — он сохранится в этом же браузере.

```bash
npm run build      # typecheck + production-сборка в dist/
npm run preview    # локальный просмотр сборки
```

## Подключение Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. **SQL Editor → New query** → вставьте целиком файл [`supabase/schema.sql`](supabase/schema.sql) → **Run**.
   Скрипт создаёт таблицы, RLS-политики, триггеры, бакеты `vault` (приватный) и `public` (картинки),
   и включает Realtime для сообщений.
3. **Project Settings → API** → скопируйте `Project URL` и `anon public key`.
4. Создайте `.env` в корне:

```env
VITE_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

5. Перезапустите `npm run dev`. В шапке появится метка **SUPABASE**, а приложение переключится
   на реальные аккаунты, базу, хранилище и realtime.

> Если в Supabase включено подтверждение почты, после регистрации придётся перейти по ссылке из письма.
> Отключить: **Authentication → Providers → Email → Confirm email**.

### Схема данных

| Таблица | Назначение |
| --- | --- |
| `profiles` | профили (ник, имя, био, аватар, ссылки) |
| `posts`, `post_likes`, `bookmarks`, `comments` | лента, реакции, закладки, комментарии |
| `friendships` | заявки и дружба (`pending`/`accepted`/`blocked`) |
| `chats`, `chat_members`, `messages` | диалоги, группы и каналы сообществ, сообщения с вложениями |
| `groups`, `group_members`, `channels` | сообщества, роли участников (`owner`/`member`), текстовые и голосовые каналы |
| `files` | метаданные личных файлов (сами файлы — в Storage-бакете `vault`) |
| `saved_tracks`, `playlists`, `playlist_tracks` | музыка пользователя и плейлисты |
| `notifications` | уведомления |

Все таблицы закрыты Row Level Security: посты читают все, личное (файлы, музыка, чаты,
уведомления) — только владелец/участники. Сообщества видны всем (их можно находить), но менять
название, каналы и удалять группу может только владелец; вступить — только от своего имени.

Если схема уже была применена раньше, просто выполните `supabase/schema.sql` ещё раз: в конце файла
есть блок «обновление старой базы» с `alter table … add column if not exists`.

## Деплой на GitHub Pages

1. Запушьте репозиторий и включите **Settings → Pages → Source: GitHub Actions**.
2. Добавьте секреты **Settings → Secrets and variables → Actions**:
   `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (необязательно — без них будет демо-режим).
3. Workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) сам соберёт проект
   и опубликует `dist/`.

База пути определяется автоматически:

* репозиторий `username.github.io` → `base: /`;
* обычный репозиторий → `base: /<repo>/`.

Маршрутизация — хеш-роутер (`#/feed`, `#/chats/123`), поэтому прямые ссылки и перезагрузка
страницы на GitHub Pages работают без серверных rewrite-правил.

Локальный деплой в «ручном» режиме:

```bash
VITE_BASE=/lulzForum/ npm run build
```

## Музыка: как это работает

LulzForum не хранит чужую музыку и не требует API-ключей — браузер обращается к открытым
каталогам напрямую:

| Источник | Что даёт | Ключ |
| --- | --- | --- |
| **Audius** | полноценные стримы, открытый протокол | не нужен |
| **iTunes Search API** | огромный каталог Apple, превью 30 с | не нужен |
| **Openverse** | Creative Commons аудио (Freesound, Jamendo и др.) | не нужен |
| **SoundCloud** | встроенный официальный виджет по ссылке | не нужен |
| **Яндекс Музыка** | официальный iframe по ссылке на трек/альбом | не нужен |
| **Zaycev.net** | поиск и метаданные через открытый mobile-API | не нужен, но нужен CORS-прокси |
| **YouTube / Bandcamp / mp3** | embed или прямой поток | не нужен |

Найденный трек можно сохранить в «Мою музыку», лайкнуть, добавить в плейлист, прикрепить к посту
или включить в общую очередь. Если источник не отдаёт поток — LulzForum показывает встроенный
плеер сервиса и ссылку на оригинал.

> Полное прослушивание в SoundCloud/Яндекс Музыке зависит от прав сервиса и вашего аккаунта в нём.
> Прямые mp3 и Audius играют внутри LulzForum без ограничений.

### Zaycev.net: зачем прокси

`api.zaycev.net` не отдаёт `Access-Control-Allow-Origin`, поэтому браузер не может обратиться к нему
напрямую. LulzForum пробует несколько путей (настройки → «Источник Zaycev.net»):

| Режим | Что делает |
| --- | --- |
| **АВТО** (по умолчанию) | сначала прямой запрос, затем публичные CORS-прокси (allorigins, codetabs, corsproxy) |
| **ПУБЛИЧНЫЙ ПРОКСИ** | только публичные прокси |
| **СВОЙ ПРОКСИ** | ваш адрес, поддерживающий `?url=…` или `%s` (Cloudflare Worker, nginx) |
| **НАПРЯМУЮ** | без прокси — сработает, если CORS когда-нибудь включат |

Свой прокси можно задать и при сборке: `VITE_ZAYCEV_PROXY=https://my-proxy.workers.dev/?url=`.
Минимальный Cloudflare Worker:

```js
export default {
  async fetch(request) {
    const target = new URL(request.url).searchParams.get('url')
    const res = await fetch(target, { headers: { 'user-agent': 'Mozilla/5.0' } })
    return new Response(res.body, {
      status: res.status,
      headers: { 'access-control-allow-origin': '*', 'content-type': res.headers.get('content-type') || 'application/json' },
    })
  },
}
```

Если Zaycev недоступен (прокси не ответил, изменился API), поиск по остальным каталогам продолжает
работать, а в тосте появляется причина. Ссылку на трек можно всё равно сохранить в библиотеку —
метаданные подтянутся при первой возможности, слушать можно на самом Zaycev.

### Архитектура

Единый интерфейс `Backend` (`src/types.ts`) описывает все операции. Две реализации —
`LocalBackend` (демо, IndexedDB) и `SupabaseBackend` (прод) — взаимозаменяемы, поэтому весь UI
не знает, где хранятся данные. Режим выбирается автоматически по наличию `VITE_SUPABASE_URL` и
`VITE_SUPABASE_ANON_KEY`.

## Приватность и безопасность

* файлы в бакете `vault` читает только владелец (RLS по первой папке пути — `auth.uid()`);
* чаты и сообщения доступны только участникам (`is_chat_member()` + RLS);
* музыка, закладки и уведомления видны только своему пользователю;
* пароли хранит Supabase Auth, приложение их не видит;
* в демо-режиме всё лежит в IndexedDB вашего браузера и никуда не отправляется;
* демо-аккаунты хранят пароль локально в открытом виде — не используйте в демо-режиме реальные пароли.
